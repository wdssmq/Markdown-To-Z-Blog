继续「不想」写的水文。。

上一篇「月报」记录的那些代码项目烧掉了当月的 Copilot 额度，还烧了不少「硅基流动」的羊毛，甚至充了 10 块钱；

> 后边才发现，Copilot 可以设置「额外预算」继续用，按量计费，而不用开更高一档的订阅；
>
> 我用了 1 刀出头，然而至今没收到付费通知，就不知道什么情况；

↑ 围绕 Z-BlogPHP 和周边工具投入了很多，然而完成后并没有什么实感，比如 1.8 的正式版感觉仍然要很久。。

「喵明明已经很努力在写代码了。。」

↑ 好吧，如标题所说，我对那些代码本身并没有太多掌控感，因为都是 AI 生成的，虽然规划和确认效果仍然略费精力；

「- -」「- -」「- -」「- -」

之后又用 WorkBuddy 的羊毛写了一个 Z-BlogPHP 插件，名字就叫「一个 Z-BlogPHP 插件」——

> wdssmq/zbp\_zberOne: 一个并不能证明什么的 Z-BlogPHP 插件
>
> [https://github.com/wdssmq/zbp_zberOne](https://github.com/wdssmq/zbp_zberOne "wdssmq/zbp\_zberOne: 一个并不能证明什么的 Z-BlogPHP 插件")

WorkBuddy 这边甚至不给你手动改文件，只能通过会话代理…… 到是有积分通用的 CodeBuddy，虽然也是基于 VSCode，然而就很不习惯；

> 我有配置硅基流动的 API Key 到 CodeBuddy 中测试，因为有积分实际并没有用中转模型，写完插件后更是好几天没会话过，因为有签到积分也没管它的开机自启，结果烧了我两块钱自付额度；
>
> 只是启动就烧额度什么的，，，姑且移除了 Key。

「- -」「- -」「- -」「- -」

10 月份空了四五天，然后把私有仓库的 Z-BlogPHP 插件公开了绝大部分，以及又写了一个配套的 Github Action —— [wdssmq/zbp-app-lint](https://github.com/wdssmq/zbp-app-lint "wdssmq/zbp-app-lint: 对 Z-BlogPHP 插件 / 主题仓库统一执行 ESLint（JS）与 PHP-CS-Fixer（PHP）工作流") ← 把 ESLint 和 PHP-CS-Fixer 塞到了一起。
